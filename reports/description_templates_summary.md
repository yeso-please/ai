# 관광지 설명 템플릿 평가 요약 (#4, #6)

- 실행일: 2026-10-09
- 모델: 기성 `mminilm-l12-v1` (`paraphrase-multilingual-MiniLM-L12-v2`), 회원 템플릿 `aihub-v1`
- 관광지 템플릿: `v0`(설명 없음) · `v1`(설명 앞 300자) · `v2`(`v1` + 콘텐츠 유형, **현재 서비스 템플릿 2**). 규칙은 [docs/templates.md](../docs/templates.md)
- 설명: 개발 RDS 관광지 설명 9,958곳 + TourAPI 추천코스 지점 설명 → 합계 11,965곳. 평가 관광지 31,337곳 중 **11,173곳(36%)**에 설명이 붙는다
- 원 리포트: `eval_mminilm-l12-v1_{v0,v1,v2}_aihub-v1*.md`, `sanity_*`, `popularity_bias_*`

## 결론

1. **설명을 붙여도 기성 모델의 추천 적중은 좋아지지 않는다.** 전체 후보에서 `v1`·`v2`는 `v0`와 신뢰구간이 겹치고 점추정은 약간 낮다. 설명이 있는 관광지만 후보로 두면 `v0`가 오히려 뚜렷이 낫다(주2 AUC 53.0% vs 49.7%, 참고 적중@10 25.1% vs 18.8%).
2. **대신 설문 → 관광지 방향성은 강해진다.** 동기 '역사와 문화 탐방' → 역사관광 효과 크기 d=+0.13 → +0.72, 스타일1 자연↔도시 +1.47 → +2.00. 설명이 관광지의 주제를 더 분명하게 만든다. 다만 "주제가 맞는 곳"과 "실제로 가서 만족한 곳"은 다르다(`sanity_mminilm-l12-v1_v0_aihub-v1.md` 해석 4와 같은 결론).
3. **설명 문장의 33%가 모델 입력 한도 128토큰을 넘어 잘린다.** 평균 30 → 88토큰, 최대 265. 서비스 템플릿 2도 같은 규칙이다.
4. **부정 표현은 여전히 실패한다.** "물놀이 싫음"(+0.0826)이 "좋음"(+0.0873)만큼 물놀이 관광지로 끌린다. 설명이 붙으면서 두 값 모두 커졌다. 제외 조건은 필터로 처리하는 결정을 유지한다.
5. **기성 모델의 취향 점수는 여전히 인기순보다 약하다.** 모든 템플릿에서 주1·주2가 인기 기준선 아래거나 비슷하다. 개선 여지는 템플릿보다 학습(#6 파인튜닝)에 있다.

## 고친 것

- `scripts/embed_offline.py`: 오프라인 문장에 콘텐츠 유형을 넘기지 않아 `v2`가 `v1`과 같은 문장이 되던 문제를 고쳤다. 서버(`app/main.py`)는 원래 넘기고 있어 서비스 벡터에는 영향이 없었다.
- `scripts/build_descriptions.py`: 추천코스 지점 설명에 문자 그대로 들어 있던 `\n`(2,794개)·`<br>`(161개)을 공백으로 바꾼다. 오염됐던 오프라인 문장 707곳이 정리됐다. 백엔드 RDS 설명은 깨끗했다.

## 다음 단계 제안

1. **설명 길이 줄이기**: 설명 앞 약 120자로 자른 새 관광지 템플릿을 같은 평가로 비교한다. 잘림을 없애고 이름·분류 비중을 지킨다. 좋으면 새 템플릿 번호로 서비스에 반영한다(관광지 벡터 전체 재생성).
2. **파인튜닝을 설명 포함 문장으로 다시 학습(#6)**: 기성 모델에서 설명은 주제 신호만 더한다. 파인튜닝 1차(`finetune_v1_summary.md`)는 `v0` 문장으로 주2 +3.7%p였다. `v2` 문장으로 학습하면 설명의 정보를 실제 만족 예측에 쓰도록 배울 수 있다. CPU는 겹당 약 1시간이라 Colab GPU가 필요하다(`docs/colab.md`).
3. **캠핑장 분류(backend)**: 레포츠(28)의 52%가 `숙박 > 캠핑`이다. 백엔드는 유형 28을 `ACTIVITY` 코스 후보로 쓴다. 분류코드 수집(backend #50) 뒤 캠핑장을 코스 후보에서 뺄지 정한다.
